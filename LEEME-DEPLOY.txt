--- INICIO ---

Sos el Lead Software Architect de la plataforma HTC. El codigo ya
esta completo y con 274 tests en verde. Tu tarea ahora es UNICAMENTE
el deploy y la validacion contra PostgreSQL real.

Contexto critico que tenes que saber:
El repositorio de PostgreSQL (src/db/pg-repository.ts y
src/v3/repository.ts) esta ESCRITO PERO NUNCA SE EJECUTO contra una
base real. Los 274 tests corren contra el repositorio in-memory.
Ese es el riesgo principal y lo primero que hay que validar.

Empeza leyendo DEPLOY.md, que tiene la guia completa y un checklist
de validacion de 7 pasos.

Pasos:
1. npm install y npm run build (backend), despues lo mismo en web/
2. Levantar PostgreSQL (Docker local o el servicio del hosting)
3. Arrancar con DATABASE_URL y HTC_AUTH_PASSWORD seteadas
4. Correr el checklist de DEPLOY.md ENTERO, en orden
5. Si algo falla en los pasos 1 a 4 del checklist, arreglalo: es
   codigo que nunca corrio, los puntos fragiles estan documentados
   al final de DEPLOY.md
6. Cuando todo pase, escribi un resumen de que se valido y que quedo
   pendiente

Reglas del proyecto (no negociables):
- Nunca inventes umbrales, reglas ni textos clinicos. Todo el
  conocimiento vive en canonical-v3/*.yaml
- Si un dato canonico falta, el sistema DEBE fallar con error
  explicito, nunca extrapolar
- No toques la logica de decision: ya esta validada contra la
  documentacion clinica de HTC
- Verifica lo que afirmes: si decis que la persistencia funciona,
  probala reiniciando el servidor

El modelo vigente es OS v3.0 (carpeta canonical-v3, API en /api/v3).
La carpeta canonical y /api son el modelo v2 anterior, que se
conserva porque las evaluaciones historicas nunca se recalculan.
